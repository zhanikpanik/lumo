# Smoke Test — Takeaway Mode

Чек-лист для проверки режима "маленькая точка на вынос" (`venue_type = 'takeaway'`).
Цель: убедиться, что приложение готово к использованию реальным клиентом.
Прогоните пункты сверху вниз; если что-то падает — фиксируйте и не идите дальше.

## 0. Подготовка

- В Supabase у venue стоит `venue_type = 'takeaway'`:
  ```sql
  select id, name, venue_type from venues where id = '00000000-0000-0000-0000-000000000010';
  ```
- В приложении очищен кэш venue (Local Storage → удалить ключ `venue-store` → жёсткий refresh Cmd+Shift+R).
  - Подготовлены 2 учётки для теста:
    - `cashier` (или `manager`/`owner`) — для всех операций
    - `waiter` — для проверки ограничений ролей
- Меню (продукты + категории) загружено хотя бы с 1 продуктом **без** модификаторов и 1 продуктом **с** модификаторами.

---

## 1. Lock + Open Shift

- Приложение стартует на `Lock`.
- Логин под `cashier`'ом по PIN → попадаем на `OpenShift` (если смены нет) или сразу на `Orders` (если смена уже была).
- Открыть смену (ввести стартовый кэш, например `0`) → попадаем на `Orders`.
- Попытка перейти на любой POS-маршрут без смены → редирект на `OpenShift`.

---

## 2. Главный экран заказов (takeaway-UI)

Ключевые отличия от ресторанного режима — проверьте все:

- **Нет floor plan**: даже если что-то нажать, экран столов не появляется.
- **Нет вкладки "Столы"** в нижнем таб-баре (видны только Меню, "Заказы", Lock).
- **Дефолтный фильтр** = "Открытые заказы" (не "Все заказы").
- В выпадающем списке статусов остались все три: "Все заказы", "Открытые заказы", "Закрытые заказы".
- **В сортировке нет варианта "По столам"** — есть только "По времени".
- Кнопка "Новый заказ" видна в левой верхней ячейке сетки заказов.

---

## 3. Создание заказа

- Нажать "Новый заказ" → попадаем в `Pos`.
- В шапке POS **нет** кнопки "Назначить стол" / "Стол N".
- В шапке POS **есть** кнопки Назад, поиск, нотификация.
- Слева — пустая панель заказа, в центре — категории, справа — продукты.
- Заголовок панели заказа не показывает "Стол ...".

### Добавление товаров

- Тапнуть на продукт **без** модификаторов → появляется строка в панели заказа с количеством 1.
- Повторный тап на тот же продукт → количество в существующей строке увеличивается до 2 (не создаётся новая строка).
- Тапнуть на продукт **с** модификаторами → автоматически открывается панель модификаторов; обязательные модификаторы помечены.
- Выбрать модификаторы → цена строки увеличивается на сумму модификаторов; вернуться к категориям через кнопку категорий.
- Изменить количество (через `+`/`-` в ItemActionsMenu) → итоговая сумма пересчитывается.

### Комментарии и удаление

- Добавить комментарий к строке (через ItemActionsMenu) → текст виден под названием.
- Добавить комментарий ко всему заказу (через `CommentModal`) → сохраняется.
- Удалить строку → исчезает из панели; итог пересчитывается.

### Возврат

- Нажать "Назад" с непустым заказом → возвращаемся на `Orders`, заказ виден в списке как "Открытый".
- Нажать "Назад" с пустым заказом → заказ удаляется (его нет в списке).

## 4. Карточка заказа (визуал)

Откройте `Orders`, посмотрите на свежий заказ:

- Номер заказа сверху слева, сумма — сверху справа (с иконкой сом).
- **НЕТ** метки "Быстрый чек" внизу карточки (в takeaway она скрыта намеренно).
- Виден краткий список блюд (одной строкой), если они есть.
- Виден комментарий заказа, если задан.
- Справа внизу — время открытия (HH:MM).
- Цвет фона зависит от статуса: открытый — нейтральный, оплаченный — зелёный, отменённый — тёмно-красный.

---

## 5. Оплата

### Cash (наличными)

- Открыть заказ, нажать "Оплата" → попадаем на `Payment`.
- Выбрать "Наличные", ввести сумму внесения, увидеть сдачу.
- Нажать "Оплатить" → во время обработки кнопка дизейблится, label меняется на "Обработка...".
- После успешной оплаты → возвращаемся на `Orders`. Заказ перешёл в статус "Оплачен" (зелёная карточка).

DB-проверки:

```sql
select id, status, total_amount, closed_at from orders where id = '<order_id>';
select id, method, amount, idempotency_key from payments where order_id = '<order_id>';
```

- `orders.status = 'paid'`, `closed_at IS NOT NULL`.
- Ровно одна строка в `payments`, `method = 'cash'`.

### Card (картой)

- Создать новый заказ → оплата картой → возврат на `Orders`.
- `payments.method = 'card'`, `cash_movements` для этого заказа **не пополняется**.

### Идемпотентность (защита от двойного тапа)

- Новый заказ → на `Payment` быстро дважды нажать "Оплатить".
- В `payments` для этого заказа **одна** строка, не две.

### Закрытие без оплаты (только cashier+)

- Под `cashier`: на `Payment` нажать "Без оплаты" → выбрать причину → подтвердить → возврат на `Orders`. Карточка стала отменённой (тёмно-красная).
- Под `waiter`: кнопка "Без оплаты" **дизейблена**, видна подсказка.

---

## 6. Просмотр оплаченных заказов

- Переключить фильтр статуса на "Закрытые заказы" → видны все оплаченные/отменённые заказы текущей смены.
- Тапнуть на оплаченный заказ → открывается `PaidCheck`, видны позиции, сумма, метод оплаты.

### Возврат (только cashier+)

- Под `cashier`: нажать "Возврат" → подтвердить.
- Заказ помечается бейджем "Возврат" (оранжевый).
- В `payments.refunded_at` появилось время.
- `cash_movements` получил строку `movement_type='refund'` для cash-оплат.
- Под `waiter`: кнопка "Возврат" **скрыта**.

### Отмена возврата

- Выбрать заказ с активным возвратом → кнопка "Отменить возврат" видна.
- Нажать → заказ снова "Оплачен", бейдж исчез, `payments.refunded_at = NULL`.

## 7. Функции (FunctionsModal)

Открыть бургер-меню в нижнем тоб-баре. Доступные пункты:

### Под cashier

- "Отчёт о продажах" → открывается, видны общие суммы за смену.
- "Информация о смене" → видны старт, текущий нал, ожидаемый кэш.
- "Инкассация" → ввести сумму → подтвердить → строка появилась в `cash_movements (movement_type='collection')`.
- "Внесение в кассу" → 500 → `cash_movements (movement_type='float_in')`, ожидаемый кэш вырос на 500.
- "Изъятие из кассы" → 200 → `cash_movements (movement_type='float_out')`, ожидаемый кэш упал на 200.
- "Изъятие" больше доступного → Alert "Недостаточно наличных".
- "Закрытие смены" — доступно.
- "Выход" — переход на `Lock`.

### Под waiter

- Пункты "Внесение", "Изъятие", "Закрытие смены" — **задизейблены**.
- "Отчёт" и "Информация о смене" — доступны.

---

## 8. Закрытие смены

- Под `cashier`: открыть "Закрытие смены" → ввести `counted_cash` (например, ровно ожидаемая сумма).
- Подтвердить → приложение возвращается на `OpenShift` (старая смена закрыта).
- Снова открыть смену → на `Orders` пусто (закрытые заказы прошлой смены не показываются).

DB-проверки:

```sql
select id, opened_at, closed_at, starting_cash, cash_total, counted_cash,
       expected_cash_at_close, cash_difference_at_close, cash_collections_total
from shifts
order by opened_at desc limit 1;
```

- `closed_at` заполнено.
- `expected_cash_at_close` = старт + кэш-продажи + float_in − refunds − collections − float_out.

## 9. Realtime / многоустройство (опционально)

Если планируется работа с двумя устройствами:

- Открыть приложение на двух устройствах (или две вкладки).
- На устройстве A создать новый заказ.
- На устройстве B этот заказ появляется в списке в течение 1–2 секунд без ручного refresh.
- Оплатить на B → на A заказ становится зелёным/закрытым автоматически.

## 10. Устойчивость к сети / перезапуску

### Outbox при оффлайне

- DevTools → Network → Offline. Оплатить заказ наличными.
- После небольшой задержки в верхней части появляется жёлтый баннер "Необсчитанных операций склада: 1".
- Сеть → Online. Тапнуть баннер ("Повторить") или подождать ~60 секунд.
- Баннер исчезает, в `inventory_movements` для заказа появились строки `reason='sale'`.

### Перезапуск

- При открытой смене перезагрузить страницу/приложение → состояние смены восстанавливается, на экране снова `Orders`.
- Незавершённый заказ (с непустыми позициями) тоже должен подтянуться из Supabase.

## 11. Регрессия (быстрые проверки)

- Меню грузится без ошибок (нет красного экрана, нет ошибки про `modifier_groups.sort_order`).
- Поиск по заказам работает (по номеру).
- Никаких видимых TypeScript-ошибок/красных экранов в основном флоу.

## 12. Откат venue_type для контроля (опционально)

После прогона takeaway-смок-теста полезно вернуться в ресторанный режим и убедиться, что restaurant-флоу не сломан:

```sql
update venues set venue_type = 'restaurant' where id = '00000000-0000-0000-0000-000000000010';
```

Очистить `venue-store` в Local Storage → жёсткий refresh:

- Floor plan и вкладка "Столы" вернулись.
- Кнопка "Назначить стол" появилась в POS.
- Метка "Быстрый чек" снова видна на быстрых чеках.

Затем вернуть обратно в takeaway, если клиент в этом режиме.
