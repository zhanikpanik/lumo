# Smoke Test — Базовые операции POS

Общие для всех режимов (`takeaway` / `restaurant`). Покрывает: логин, смены, заказы, оплату, возвраты, кассу, outbox, перезапуск.

Перед прогоном убедись что выполнена [подготовка ресторана](./smoke-test-restaurant-delta.md#0-подготовка).

---

## 0. Подготовка

- [ ] В Supabase есть минимум 1 продукт **без** модификаторов и 1 продукт **с** модификаторами.
- [ ] Подготовлены две учётки:
  - `cashier` (или `manager`) — для всех операций
  - `waiter` — для проверки ограничений ролей
- [ ] Приложение запущено, кэш `venue-store` очищен.

---

## 1. Логин и открытие смены

- [ ] Приложение стартует на `Lock`.
- [ ] Логин под `cashier` по PIN → попадаем на `OpenShift` (если смены нет) или сразу на `Orders` (если уже есть).
- [ ] Открыть смену (стартовый кэш, например `0`) → попадаем на `Orders`.
- [ ] Попытка перейти в POS без открытой смены → редирект на `OpenShift`.

---

## 2. Создание заказа

- [ ] Открыть POS (тап по столу или «Новый заказ»).
- [ ] В шапке: кнопка Назад, поиск, нотификация.
- [ ] Слева — панель заказа, в центре — категории, справа — продукты.

### Добавление товаров

- [ ] Тапнуть продукт **без** модификаторов → строка в панели с количеством 1.
- [ ] Повторный тап на тот же продукт → количество ++ (не новая строка).
- [ ] Тапнуть продукт **с** модификаторами → открывается панель модификаторов; обязательные помечены.
- [ ] Выбрать модификаторы → цена строки увеличилась на сумму модификаторов.
- [ ] Изменить количество (`+`/`-`) → сумма пересчитывается.

### Комментарии и удаление

- [ ] Добавить комментарий к строке → текст виден под названием.
- [ ] Добавить комментарий ко всему заказу → сохраняется.
- [ ] Удалить строку → исчезает, итог пересчитан.

### Назад с заказом

- [ ] «Назад» с позициями → заказ виден в `Orders` как «Открытый».
- [ ] «Назад» с пустым заказом → заказ удаляется, в списке его нет.

---

## 3. Оплата

### Наличные

- [ ] Открыть заказ → «Оплата» → `Payment`.
- [ ] «Наличные» → ввести сумму внесения → видна сдача.
- [ ] «Оплатить» → кнопка дизейблится («Обработка...»).
- [ ] Успешная оплата → возврат на `Orders`. Заказ «Оплачен» (зелёный).

DB:
```sql
select id, status, total_amount, closed_at from orders where id = '<order_id>';
select id, method, amount, idempotency_key from payments where order_id = '<order_id>';
```
- [ ] `orders.status = 'paid'`, `closed_at IS NOT NULL`.
- [ ] Ровно одна строка в `payments`, `method = 'cash'`.

### Карта

- [ ] Новый заказ → оплата картой.
- [ ] `payments.method = 'card'`. `cash_movements` для этого заказа нет.

### Идемпотентность (двойной тап)

- [ ] Новый заказ → на `Payment` быстро дважды «Оплатить».
- [ ] В `payments` **одна** строка, не две.

### Закрытие без оплаты

- [ ] Под `cashier`: «Без оплаты» → причина → подтвердить. Карточка отменённая (тёмно-красная).
- [ ] Под `waiter`: кнопка «Без оплаты» **дизейблена**.

---

## 4. Просмотр оплаченных заказов

- [ ] Фильтр «Закрытые заказы» → видны оплаченные/отменённые заказы.
- [ ] Тапнуть оплаченный → `PaidCheck`: позиции, сумма, метод оплаты.

### Возврат

- [ ] Под `cashier`: «Возврат» → подтвердить. Бейдж «Возврат» (оранжевый).
- [ ] `payments.refunded_at` заполнен.
- [ ] Для cash-оплат: `cash_movements` → `movement_type='refund'`.
- [ ] Под `waiter`: кнопка «Возврат» **скрыта**.

### Отмена возврата

- [ ] Заказ с возвратом → «Отменить возврат».
- [ ] Заказ снова «Оплачен», бейдж исчез, `payments.refunded_at = NULL`.

---

## 5. Функции (бургер-меню)

### Под cashier

- [ ] «Отчёт о продажах» → открывается, суммы за смену.
- [ ] «Информация о смене» → старт, текущий нал, ожидаемый кэш.
- [ ] «Инкассация» → сумма → `cash_movements (movement_type='collection')`.
- [ ] «Внесение в кассу» → 500 → `cash_movements (movement_type='float_in')`, ожидаемый кэш +500.
- [ ] «Изъятие из кассы» → 200 → `cash_movements (movement_type='float_out')`, ожидаемый кэш −200.
- [ ] «Изъятие» > доступного → Alert «Недостаточно наличных».
- [ ] «Закрытие смены» — доступно.
- [ ] «Выход» — переход на `Lock`.

### Под waiter

- [ ] «Внесение», «Изъятие», «Закрытие смены» — **задизейблены**.
- [ ] «Отчёт» и «Информация о смене» — доступны.

---

## 6. Закрытие смены

- [ ] Под `cashier`: «Закрытие смены» → ввести `counted_cash`.
- [ ] Подтвердить → возврат на `OpenShift`.
- [ ] Открыть новую смену → `Orders` пуст.

DB:
```sql
select id, opened_at, closed_at, starting_cash, cash_total, counted_cash,
       expected_cash_at_close, cash_difference_at_close, cash_collections_total
from shifts
order by opened_at desc limit 1;
```
- [ ] `closed_at` заполнен.
- [ ] `expected_cash_at_close` = старт + кэш-продажи + float_in − refunds − collections − float_out.

---

## 7. Realtime / несколько устройств

- [ ] Два устройства (или две вкладки) с одним venue.
- [ ] Устройство A: создать заказ.
- [ ] Устройство B: заказ появился в списке за 1–2 сек (без ручного refresh).
- [ ] Оплатить на B → на A заказ стал закрытым автоматически.

---

## 8. Устойчивость к сети / перезапуск

### Outbox (офлайн)

- [ ] DevTools → Network → Offline. Оплатить заказ наличными.
- [ ] Жёлтый баннер «Необсчитанных операций склада: 1».
- [ ] Сеть → Online. Тапнуть «Повторить» или ждать ~60 сек.
- [ ] Баннер исчез. `inventory_movements` для заказа → `reason='sale'`.

### Перезапуск

- [ ] При открытой смене перезагрузить приложение → состояние смены восстановлено, снова `Orders`.
- [ ] Незавершённый заказ (с позициями) подтянулся из Supabase.

---

## 9. Регрессия

- [ ] Меню грузится без ошибок (нет красного экрана).
- [ ] Поиск по заказам работает (по номеру).
- [ ] Нет видимых TypeScript-ошибок / красных экранов в основном флоу.

---

## Если что-то не работает

1. Запиши шаг, на котором упало, и что ожидалось.
2. DevTools → Console + Network — приложи логи.
3. SQL-проверки из секции — проблема в UI или в данных.
4. Дай ассистенту: шаг + что увидел + что должно было быть.
