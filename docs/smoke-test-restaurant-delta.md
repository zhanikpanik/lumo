# Smoke Test — Restaurant Delta

Дельта-чек-лист поверх [smoke-test-takeaway.md](./smoke-test-takeaway.md).
Проверяем только то, чего **нет** в режиме takeaway: столы, floor plan, привязка заказа к столу, гостей, и сортировка по столам.

Все общие фичи (логин, смены, продукты, модификаторы, оплата, возвраты, инкассация, outbox, dead-letter, перезапуск, идемпотентность) уже покрыты в takeaway-смок-тесте — их повторно прогонять не надо.

## 0. Подготовка

- [ ] У venue выставлен `venue_type = 'restaurant'`:
  ```sql
  update venues set venue_type = 'restaurant' where id = '00000000-0000-0000-0000-000000000010';
  select id, name, venue_type, track_guests from venues where id = '00000000-0000-0000-0000-000000000010';
  ```
- [ ] Очищен кэш `venue-store` в Local Storage → жёсткий refresh приложения.
- [ ] В Supabase есть как минимум 1 zone (`zones`) и в ней 4+ столов (`tables`) с заданными `col`/`row`/`col_span`/`row_span`.
- [ ] Открыта смена под `cashier`.

---

## 1. Floor plan (новое относительно takeaway)

- [ ] В нижнем таб-баре **появилась** вкладка "Столы".
- [ ] Переключиться на "Столы" → видна сетка с расставленными столами по зонам.
- [ ] Если зон > 1 — навигация между зонами работает (если есть UI переключения зон).
- [ ] Столы отображают свой `number`. Свободные — нейтральный фон, занятые — зелёный/жёлтый.
- [ ] Размеры столов соответствуют `col_span`/`row_span` (квадратные / широкие / высокие).

---

## 2. Заказ на столе (главный отличающий флоу)

### Создание заказа на стол

- [ ] Тап по **свободному** столу → попадаем на `Pos`.
- [ ] В шапке POS видна кнопка "Стол N" (или "Назначить стол", если стол ещё не назначен).
- [ ] Заголовок панели заказа отражает номер стола.
- [ ] Добавить продукт → строка появляется, сумма растёт.
- [ ] Нажать "Назад" → возвращаемся на floor plan; стол **занят** (цветной), на нём видна сумма заказа.

DB-проверки:
```sql
select id, number, table_id, table_number, zone_name, status, is_quick_check, guest_count
from orders
where id = '<order_id>';
```
- [ ] `table_id` заполнен, `table_number` совпадает с тапнутым столом, `is_quick_check = false`, `status = 'active'`.

### Открытие существующего заказа

- [ ] Тапнуть по **занятому** столу → попадаем на `Pos`, открывается тот же заказ (с уже добавленными позициями).
- [ ] Никакого нового заказа не создаётся (`orders` строка одна для этого стола).

### Оплата освобождает стол

- [ ] Из заказа на столе → "Оплата" → наличные → "Оплатить".
- [ ] После возврата на `Orders` переключиться на "Столы" → стол снова свободен (нейтральный).

### Закрытие без оплаты (cancelled)

- [ ] Под `cashier`: открыть свежий заказ на столе → "Оплата" → "Без оплаты" → причина → подтвердить.
- [ ] Стол освободился, заказ в списке как отменённый.

---

## 3. TablePicker (переназначение стола)

- [ ] Создать "Быстрый чек" (через кнопку "+", если она есть, или другим путём).
- [ ] В POS у быстрого чека в шапке видна кнопка "Назначить стол".
- [ ] Тапнуть → открывается `TablePicker` → видна сетка свободных столов.
- [ ] Выбрать стол → возвращаемся в POS, заказ теперь привязан к столу.
- [ ] DB: `orders.table_id` и `orders.table_number` обновились, `is_quick_check` мог остаться/измениться (зависит от логики — проверьте, что соответствует ожиданию).

### Переназначение между столами

- [ ] Снова нажать "Стол N" в POS → открывается `TablePicker`.
- [ ] Выбрать другой свободный стол → старый освобождается, новый занимается.
- [ ] Попытаться назначить **занятый** стол → ожидаем либо предупреждение, либо предложение объединить (зависит от UX — проверьте, что нет тихой потери данных).

---

## 4. Быстрый чек (quick check) рядом со столами

В отличие от takeaway, в ресторанном режиме quick check — это альтернативный путь:

- [ ] Создать quick check (если есть кнопка "+" или другой запуск) → попадаем в POS без стола.
- [ ] В шапке кнопка "Назначить стол" (т.к. стола нет).
- [ ] На карточке заказа в `Orders` видна метка "**Быстрый чек**" (в takeaway она была скрыта).
- [ ] Quick check можно оплатить как обычный заказ — стол при этом не задействуется.

---

## 5. Сортировка "По столам"

- [ ] Создать 3–4 заказа на разных столах (например, столы №3, №7, №1, №5).
- [ ] В `Orders` открыть выпадающее меню сортировки → выбрать "По столам".
- [ ] Список перестроился: заказы идут в порядке возрастания номера стола (1, 3, 5, 7).
- [ ] Quick check без стола идёт в конце (или в начале — главное, что не падает).
- [ ] Переключиться обратно на "По времени" → список снова отсортирован по `opened_at`.

---

## 6. Счётчик гостей (только при `track_guests = true`)

Если у venue `track_guests = true`, в шапке POS должен появиться счётчик гостей:

```sql
update venues set track_guests = true where id = '00000000-0000-0000-0000-000000000010';
```
(после изменения — очистить кэш `venue-store` и обновить страницу)

- [ ] В шапке POS виден счётчик гостей: текущее значение + кнопки `+` / `−`.
- [ ] `−` дизейблится при значении `1` (минимум).
- [ ] Изменения значения сохраняются в `orders.guest_count`.
- [ ] При `track_guests = false` (откатить):
  ```sql
  update venues set track_guests = false where id = '00000000-0000-0000-0000-000000000010';
  ```
  → счётчик скрыт.

## 7. Роль waiter на столах

- [ ] Залогиниться под `waiter`.
- [ ] Видна вкладка "Столы" в таб-баре, можно тапать на столы и создавать заказы.
- [ ] В POS: добавление продуктов, модификаторов, комментариев — работает.
- [ ] В `Payment`: "Без оплаты" дизейблено для waiter (этот случай уже покрыт в общих role-guards).
- [ ] В `PaidCheck`: кнопка возврата скрыта для waiter (этот случай уже покрыт).

---

## 8. Откат / повторный прогон takeaway

Когда закончили — можно либо оставить venue в `restaurant`, либо вернуть в `takeaway` для production-точки на вынос. **Не забывайте чистить кэш `venue-store` после смены `venue_type`** — иначе UI 30 секунд будет показывать старый режим.
